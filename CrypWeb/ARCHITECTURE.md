# CrypWeb architecture

A short map for maintainers. The user-facing description and the list of supported features are in [README.md](README.md).

## The big picture

```
 .cwm template ──CwmReader──▶ WorkspaceModel ──▶ WorkspaceEditor (undo, selection, copy/paste)
                                   │                     │
                                   │                     └─▶ Home.razor (SVG canvas, ribbon, dialogs)
                                   ▼
                             ExecutionEngine ──▶ plugin code (original CT2 sources, CrypWeb.Plugins)
                                   │                     │
                                   │                     └─▶ presentations (WPF controls from CrypWeb.Wpf → HTML)
                                   └─▶ RunView (what the canvas shows: state, progress, results)
```

| Project | Role | WPF-free? |
|---|---|---|
| `CrypWeb.Core` | Workspace model, `.cwm` reader/writer, execution engine, template texts, localization of plugin metadata | yes |
| `CrypWeb.App` | The Blazor WebAssembly app: canvas, ribbon, palette, settings, engine host | – |
| `CrypWeb.Wpf` | The subset of WPF that plugins and their presentations use (elements, layout, XAML loader, bindings, 3D, …), rendered to HTML/SVG. See its [README](CrypWeb.Wpf/README.md) | – |
| `CrypPluginBase.Portable` | Links the original `CrypPluginBase` sources and adds shims | – |
| `CrypWeb.Plugins` / `.Isolated` | Compile the original `CrypPlugins/` sources unchanged; browser replacements for OS APIs (crypto, sockets, images, audio, …) | – |
| `CrypWeb.Drawing` | Managed `System.Drawing` replacement (the real one is Windows only) | – |
| `CrypWeb.Tests` | Command-line checks over all templates and presentations | – |

## Where to look when …

| You want to … | Start here |
|---|---|
| change how the canvas reacts to the mouse | `CrypWeb.App/Pages/Home.Pointer.cs` (gestures), `Home.View.cs` (zoom, fit) |
| change wire routing | `Home.Wires.cs` (hops, dragging segments), `Home.Geometry.cs` (`AutoRoute`) |
| change what is drawn for a component (size, ports, bubbles) | `Home.Geometry.cs`, `Home.Metadata.cs`, `Home.razor` |
| change running / stopping, or what the engine reports back | `Home.Execution.cs`, `Engine/EngineHost.cs`, `CrypWeb.Core/ExecutionEngine.cs` |
| open / save files and templates | `Home.Files.cs`, `Home.Documents.cs`, `CrypWeb.Core/CwmReader.cs`, `CwmWriter.cs` |
| change the start center or the About dialog | `Components/StartPage.razor`, `Components/AboutModal.razor` |
| change the settings dialog / settings page | `Components/SettingsModal.razor`, `Components/SettingsPage.razor`, `CrypWeb.Core/SettingsSchema.cs` |
| change which connections are allowed | `CrypWeb.Core/ConnectionRules.cs` |
| change undo/redo, copy/paste, the JSON format | `CrypWeb.Core/WorkspaceEditor.cs`, `WorkspaceEditor.Json.cs` |
| change how a plugin is run (settings, outputs, presentation) | `CrypWeb.Core/PluginComponent.cs`; browser-native in/outputs: `NativeComponent.cs` |
| support another WPF control or property in a presentation | `CrypWeb.Wpf/Controls`, `Rendering/HtmlRenderer*.cs`, `Markup/` |
| add a UI language | `CrypWeb.App/Localizer.cs`, `wwwroot/i18n/` |
| change the command palette, minimap, runtimes, dropping onto wires | `Home.CommandPalette.cs`, `Home.Minimap.cs`, `Home.Insight.cs`, `Home.Splice.cs` |
| change links to templates (format, link manager) | `CrypWeb.App/TemplateLink.cs`, `Components/LinkManager.razor`, `Home.Links.cs` |
| change offline use (caching, installable app) | `wwwroot/service-worker.js`, `wwwroot/manifest.webmanifest`, `wwwroot/vfs.js`, `Home.Offline.cs` |
| add a plugin to the build | `plugins.exclude`, `plugins.isolate`, then `python3 tools-gen-plugins.py` |

`Home` is one Blazor component split into partial classes, one per concern (`Home.<Concern>.cs`). The shared state
(documents, selection, pan/zoom, drag state) lives in `Home.razor.cs`; the markup is `Home.razor`.

## Source file conventions

- One file per larger type (`BindingExpression.cs`); small related types share a file (`Triggers.cs`).
- Files that replace a desktop-only library start with a comment that says what is replaced and why
  (`CrypWeb.Plugins/EmguCV.cs`, `ManagedCrypto.cs`, `LoopbackNetwork.cs`, `CrypWeb.Drawing/Drawing.cs`, ...).
- In `CrypWeb.Wpf` and `CrypWeb.Drawing` a type with the name of a WPF / System.Drawing type mirrors it; only deviations are
  documented.

## Generated files (do not edit by hand)

| File | Generated by |
|---|---|
| `CrypWeb.App/wwwroot/plugins.json` (metadata of all components) | `tools-gen-plugins.py` |
| `CrypWeb.Plugins/plugins.g.props`, `isolated.g.props`, `libraries.g.json`, `CrypWeb.Plugins.Isolated/` | `tools-gen-plugins.py` (inputs: `plugins.exclude`, `plugins.isolate`) |
| `CrypWeb.Core/IsolatedAssemblies.g.cs` | `tools-gen-plugins.py` |
| `CrypWeb.Plugins/presentations.g.props`, `Presentations/**/*.g.cs` | `tools-gen-presentations.py` (input: `presentations.include`) |
| `CrypWeb.Wpf/Media/Colors.g.cs` | `CrypWeb.Wpf/tools/gen-colors.py` |
| virtual file system `manifest.json` | `tools-gen-vfs.py` |
| `CrypWeb.App/wwwroot/docs/` (documentation: index, one JSON per component, articles, pictures) | `tools-gen-docs.py` (run by `tools-build-web.sh`; inputs: `plugins.json`, the plugins' `doc.xml`, `Templates/**/*.xml`, `OnlineDocumentationGenerator/StaticDocs`) |
| `CrypWeb.App/wwwroot/offline.json` (file lists of the offline dialog) | `tools-gen-offline.py` (run by `tools-build-web.sh`; needs the templates, `vfs/` and `wpf-res/`) |

## Verifying a change

```bash
dotnet build CrypWeb.App
dotnet run --project CrypWeb.Tests -- ../Templates runall   # all templates + all presentations, takes several minutes
dotnet run --project CrypWeb.Tests -- ../Templates roundtrip # .cwm read → write → compare
```

## Conventions

- See `.editorconfig`: one statement per line, Allman braces, lines up to ~160 characters (tables of API declarations may exceed it).
- Public and non-obvious members get an XML doc comment that says *why* (WPF semantics being mimicked, CT2 behaviour being kept).
- Behaviour that mirrors WPF or CrypTool 2 says so in a comment, so a maintainer can compare with the original.
- Original plugin sources in `CrypPlugins/` are only touched to fix bugs that also exist on the desktop.

# CrypWeb.Wpf – WPF for the web

The part of the WPF API that the CrypTool 2 plugins use, implemented as a real element tree that is drawn as HTML/SVG.
Plugin presentations (XAML + code-behind) compile and run against it unchanged.

| Folder | Content |
|---|---|
| `Core/` | `DependencyObject`/properties, `UIElement`, `FrameworkElement`, resources and styles, dispatcher, layout value types |
| `Controls/`, `Shapes/`, `Documents/` | panels, controls, lists, shapes, inlines and flow documents |
| `Media/` | brushes, colours (`Colors.g.cs`, generated by `tools/gen-colors.py`), transforms, geometries, pictures, animations |
| `Data/` | bindings (evaluated on read), property paths |
| `Input/` | routed events, mouse/keyboard event types |
| `Markup/` | XAML loader: type resolution, value conversion, markup extensions, `XamlDiagnostics` |
| `Rendering/` | `HtmlRenderer`: element tree -> HTML/SVG; the browser does the layout (CSS grid/flex) |
| `Hosting/` | `PresentationHost`: renders on change, dispatches input from the browser |
| `Legacy/` | small WPF and .NET Framework types plugin code uses outside presentations (`Point`, `Size`, `Rect`, validation rules, converters, ...) |

## How it works

1. The generated `InitializeComponent()` calls `XamlLoader.LoadComponent`, which builds the tree from the embedded XAML,
   assigns the named fields and connects event handlers.
2. Every property or collection change bumps `RenderVersion`. A `PresentationHost` renders again when the version moved.
3. `HtmlRenderer` writes the tree: `Grid` -> CSS grid, `StackPanel` -> flex, `Canvas` -> absolute boxes, shapes -> SVG.
   What needs measuring (view boxes, shape extents) is finished in the browser by `wpf.js`; the styles are in `wpf.css`.
4. The browser reports clicks, text, slider values and selections; `PresentationHost.Dispatch` raises the WPF events.
5. Animations and `DispatcherTimer`s advance on `WpfRuntime.Tick()` (called by the worker about every 50 ms).

## Adding missing API

Add a plugin folder to `presentations.include`, run `python3 tools-gen-presentations.py` and build. Compile errors name the
missing types/members; unknown XAML elements and attributes are listed by `XamlDiagnostics` (printed by the `runall` test).
Layout is the browser's job: `ActualWidth`/`ActualHeight` are only known for explicit sizes.

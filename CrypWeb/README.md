# CrypTool 2 Web (prototype)

Browser/WebAssembly version of the CT2 workspace canvas (Blazor WASM).

- `CrypPluginBase.Portable` – original CrypPluginBase sources linked, WPF types shimmed (net10).
- `CrypWeb.Core` – WPF-free `.cwm` reader, workspace model, template `$placeholder$` resolution.
- `CrypWeb.App` – Blazor WebAssembly app: SVG canvas (pan/zoom/fit), template browser.
- `CrypWeb.Tests` – parses all templates (`dotnet run --project CrypWeb.Tests -- ../Templates`).

Run: `./tools-copy-templates.sh && dotnet run --project CrypWeb.App --urls http://localhost:5199`

Canvas features: move (multi/Shift-select, marquee, snap, arrow-key nudge), resize, pan (middle/right/Space), zoom at cursor, fit/100%,
connect ports by drag (type-checked, re-route by dragging an input), select/delete wires, add components (palette drag/double-click) and notes,
rename (double-click title), collapse, copy/paste/duplicate, undo/redo, open .cwm/.json, save .json.

Execution: `CrypWeb.Core/ExecutionEngine.cs` re-implements the CT2 workspace semantics (queued inputs, mandatory inputs, back-pressure) single-threaded.
`CrypWeb.Plugins` compiles the original plugin sources unchanged against the portable plugin base (WPF types shimmed).
Plugins that need WPF/extra libraries are listed in `plugins.exclude` (generated by `tools-prune-plugins.py`) and are shown but not runnable.
TextInput/TextOutput/NumberInput/BooleanInput/BooleanOutput have browser-native replacements (`NativeComponent`).

Regenerate metadata/icons/compile list: `python3 tools-gen-plugins.py`; re-prune after changing shims: `python3 tools-prune-plugins.py`.

Not yet: control (IControl) connectors, plugin presentations, settings UI beyond raw values, saving back to .cwm.

## Localization (en / de)

- **UI strings:** `CrypWeb.App/Localizer.cs` + `wwwroot/i18n/<lang>.json` (English is the fallback). Add a language by adding a JSON file and listing it in `Localizer.Languages`. The picker is in the ribbon, the choice is stored in `localStorage` (default: browser language).
- **Plugin metadata:** `tools-gen-plugins.py` reads `Resources.<lang>.resx` next to each `Resources.resx` and writes the differences into `plugins.json` (`loc.<lang>`: name, tooltip, port captions/tooltips). Use `PluginMeta.NameFor/TooltipFor/PortCaptionFor/PortTooltipFor(lang)` (`CrypWeb.Core/Localization.cs`), English is the fallback.
- **Templates:** `$placeholders$` and note texts come from the template's `.xml` (`TemplateStrings.Load(xml, lang)`). They are resolved when a template is loaded, so an unmodified template is reloaded when the language changes.
- **Engine worker:** `ct2engine.start` passes the selected culture; the worker sets `CurrentUICulture`. Localized plugin resources (`Resources.<lang>.resx`) are embedded as satellite resources of `CrypWeb.Plugins` and loaded with `loadAllSatelliteResources`, so plugin log messages and exceptions use the selected language.
- **Not localized yet:** component names given in a saved workspace (user-chosen), tooltips of the ribbon buttons, error messages of the app itself, plugin setting captions (the settings modal reuses the same lookup).

## File compatibility with CrypTool 2

Save writes a normal `.cwm` (gzip + CT2 "XMLSerialization" object graph) that the desktop version opens; Open reads `.cwm` (and the internal `.json`).
`CwmReader` keeps every serialized field it does not model (`Extra`), `CwmWriter` replays them, so unmodelled data survives a round trip.
Verified with `dotnet run --project CrypWeb.Tests -- ../Templates roundtrip` (read -> write -> compare field by field): all 281 templates; 19 differ only
because the writer drops orphaned objects that the original files carry (connections/connectors of already deleted components) and de-duplicates doubled list entries.
Known limits: text boxes keep their formatting only while the text is not edited (edited notes are written as plain text), `$placeholders$` of templates are
already replaced when a template is loaded (so a saved template contains the localized texts), wire routes are re-routed by the desktop when components were moved,
settings of types other than string/int/bool/double/enum cannot be restored by the desktop loader. Not tested against a real CrypTool 2 installation.

## Running the original plugins unchanged (how the gaps are closed)

The plugin sources in `CrypPlugins/` are never edited. Everything the browser lacks is provided on the build side:

| Problem | Solution |
|---|---|
| WPF types in plugin code | `CrypPluginBase.Portable/Shims/` – behaviour where plugins use it (dependency properties, converters, validation rules, `Point/Size/Rect`), generated stand-ins for everything that only draws (`tools-prune-plugins.py` -> `CrypWeb.Plugins/stubs.g.cs`). Calls on a stand-in are recorded and shown in the right panel ("presentation data"). |
| Plugins with identical type names (e.g. several `Properties.Resources`) | each gets its own assembly (`plugins.isolate`, generated projects in `CrypWeb.Plugins.Isolated/`) |
| `System.Drawing.Common` (Windows only) | `CrypWeb.Drawing`: managed `Bitmap/Graphics/Pen/Brush/Font/...` on a pixel buffer, codecs by ImageSharp. Text is laid out but not drawn. |
| OS crypto (`Aes`, `RijndaelManaged`, DES, 3DES, RC2) | `CrypWeb.Plugins/ManagedCrypto.cs`: same names in the global namespace (found before `using System.Security.Cryptography`), BouncyCastle inside; verified against .NET (`CrypWeb.Tests`) |
| `NativeCryptography` (C++/CLI) | `CrypWeb.Plugins/NativeCryptoShim.cs` |
| Data files read from disk | lazy files in the worker's virtual file system (`tools-gen-vfs.py`) |
| WPF-only input/output components | browser-native components (`NativeComponent`: text/number/boolean in-/output, picture output) |

Workflow after changing shims or plugin sources: `python3 tools-prune-plugins.py` (finds what compiles, writes `plugins.exclude`/`plugins.isolate`/stubs state), then `./tools-build-worker.sh`.

Status (headless smoke test over all templates, `dotnet run --project CrypWeb.Tests -- ../Templates runall`): 226 of 241 templates run without errors,
213 of them with real plugins; the rest are components that still need their own web view or libraries (Enigma, KeySearcher and the other analyzers
with custom WPF controls, Emgu/NAudio-based ones, the cloud components).
Plugin visualizations: the calls a component makes on its (browser-less) presentation are recorded in the engine worker (`RunNode.Pres`), converted to plain data (`ToPlain`: 2D arrays, lists, dictionaries, numbers, text) and shown by the generic **Open view** dialog (`PresentationModal`/`ValueView`: grids as tables, 0/1 series as cells, number series as bar charts, objects as key/value tables). This is a data view, not the component's original WPF drawing. Per-plugin renderers (e.g. an Enigma machine, histograms) would be added on top of the same data.
Not done: text drawing in `CrypWeb.Drawing`, webcam/audio via browser APIs.

### Plugin visualizations that look like the WPF originals

Three layers, picked in this order by `VisualizerRegistry.Find` (`CrypWeb.App/Visualizers/`):

1. **Custom visualizers** (`*Viz.razor`, `[Visualizer("PluginType")]`): hand-written Razor for presentations whose look is data-driven
   (Huffman, NLFSR, M209/Hagelin, StraddlingCheckerboard, SyllabaryCipher, JosseCipher, Contains, BerlekampMassey, Progress ...).
2. **Generic XAML drawing** (`XamlViz` + `XamlRenderer`): `tools-gen-xaml.py` copies every plugin's presentation `.xaml`, the images it references
   and the plugin string resources (`{Loc Key}`) to `wwwroot/xaml/` (index: `xaml/index.json`). `XamlRenderer` draws the *original* XAML as
   HTML/SVG: Grid (row/column definitions, spans), StackPanel/WrapPanel/Canvas/Border/Viewbox/TabControl, TextBlock/Label (+ inlines), Button/CheckBox,
   Rectangle/Ellipse/Line/Polygon/Path (path mini-language, `PathGeometry` figures, geometry groups), Image, gradients and the
   Render/Layout transforms (translate/scale/rotate/skew/matrix, groups). Roots with a design size and Viewboxes are scaled to the available space (`ctXamlFit` in `canvas.js`).
3. **Live state**: the stand-in presentation objects (`stubs.g.cs`) return a recording proxy for every named element
   (`StubValue(owner, path)`): `presentation.ScoreValue.Text = "42"` is recorded as `ScoreValue.Text=` (and read back later, as the plugin may
   `int.Parse` it). `XamlAdapters.Generic` applies `Text/Content/Header`, `Visibility` and `Fill/Background/Foreground` writes to the drawn elements;
   `XamlAdapters.byPlugin` holds plugin specific mappings (e.g. T9Code: `SetNumbersToDisplay` -> `Display.Text`).

Limits: code-behind of the presentation (animations, slide logic, data templates, bindings) is not executed, so views that build their content in C#
(Enigma rotors, AES/Keccak slide shows) show their static XAML only.

## Hosting on Cloudflare Workers

The app is static (Blazor WASM + engine worker), so it is deployed as Workers *static assets* (`wrangler.jsonc`, SPA fallback to `index.html`).

```sh
npm install
npm run build            # ./tools-build-web.sh: templates + engine worker + dotnet publish -> dist/
npm run dev              # local Workers runtime at http://localhost:8787
npx wrangler login       # once
npm run deploy           # build + wrangler deploy
```

Limits: 25 MiB per file / 20,000 files per version (currently ~1,700 files, largest ~9 MB). `.github/workflows/crypweb-deploy.yml` deploys manually
(needs the repo secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`).


## Plugin visualizers (original-style drawings)

The desktop version draws each plugin with its own WPF control. The web app replaces these drawings with Blazor components in
`CrypWeb.App/Visualizers/`, **without touching any plugin source**, so `CrypPlugins/` can keep being synced from the upstream fork:

- A visualizer only reads the calls a plugin already makes against its presentation (`NodeView.Pres`: call name -> last JSON arguments).
- A component inherits `VizBase` and declares which plugin types it draws: `@attribute [Visualizer("M209", "HagelinMachine")]`
  (short or full type name). `VisualizerRegistry` finds them by reflection; the component window on the canvas and the view dialog use them
  automatically (the dialog offers "Raw data" as fallback), so plugins without a visualizer keep the generic data view.
- To add one: create `Visualizers/<Name>Viz.razor`, look at the plugin's call names with `dotnet run --project CrypWeb.Tests -- <templates> prescalls`,
  and render those. If the plugin's arguments are a type `ExecutionEngine.ToPlain` does not know yet, extend that once (generic, not per plugin).
- If upstream renames a presentation call, the visualizer shows nothing instead of breaking the plugin.

Available: wheel machines (M209, Hagelin), Huffman, NLFSR, tables (StraddlingCheckerboard, SyllabaryCipher).
